# 05 — Attack Taxonomy Through a Discovery Lens

*Part of a multi-file report — see `00-INDEX-executive-summary.md` for the map. Full technical mechanics for every family below are covered in companion ARX report `04` and companion general-cryptography report `04`; this file's distinct contribution is answering, for each family, "what specific observation would make an expert reach for this technique first" — the trigger, not the mathematics.*

---

| Attack family | The trigger — what you'd have just noticed | The warning sign it targets (`03`) |
|---|---|---|
| **Differential** | A round function whose nonlinear component (S-box or addition) has *any* measurably non-uniform differential behavior, and a round count that doesn't obviously dwarf the number of rounds needed to average that non-uniformity out | Weak nonlinearity, insufficient rounds |
| **Linear** | The same non-uniformity, viewed through correlation rather than probability — reached for specifically when known-plaintext access is more realistic for the target's actual deployment than chosen-plaintext access | Weak nonlinearity, insufficient rounds |
| **Rotational / RX** | Repeated round structure with rotation constants that share a visible relationship to each other, or round constants that don't obviously break rotational symmetry on inspection | Symmetry, weak constants |
| **Boomerang / rectangle** | A cipher where the best single differential trail you can find dies out partway through the rounds, but the *first half* and *second half* each independently show a strong, short trail — the natural next move when a straight differential search plateaus | Weak nonlinearity (in two separate, shorter doses) |
| **Impossible differential** | A round function structured enough (often SPN-like, with a clean linear diffusion layer) that you can reason, by hand, about propagations that are *provably* zero-probability — reached for specifically when the design's diffusion layer has clean enough algebraic structure to make "impossible" propagations easy to identify analytically | Weak topology (used as a sieve, not a direct break) |
| **Related-key** | Any key schedule simpler or more linear than the round function it feeds (`03`'s "weak key schedules" recursive check) — the specific trigger is noticing the key schedule *itself* would fail this file's other checks if treated as its own small cipher | Weak key schedules |
| **Integral / higher-order differential** | A round function with visibly low algebraic degree, or a design where an attacker can structure a set of chosen inputs (all values of one word, fixed elsewhere) cheaply | Low algebraic degree |
| **Invariant subspace** | A round function built from operations that individually preserve some algebraic property (e.g., every operation happens to map a specific affine subspace to itself) — a harder trigger to notice cheaply (`03`'s own entry says so directly), usually motivated by a specific, informed guess rather than a generic scan | Invariant subspaces |
| **Cube attacks** | The same low-algebraic-degree trigger as integral attacks, but reached for specifically when the target is a stream cipher or a keyed mode (MAC, keyed permutation use) where the attacker can influence public IV/nonce bits directly — Keccak's keyed-mode cube-attack lineage (`04`) is the clean, current illustration of exactly this trigger being present (keyed mode) where it wasn't for the unkeyed hash use | Low algebraic degree, weak permutations (keyed vs. unkeyed) |
| **Meet-in-the-middle** | A cipher or mode whose structure visibly decomposes into two independently-computable halves (forward from plaintext, backward from ciphertext, or forward/backward through a permutation's rounds) | Weak topology, poor mixing |
| **Algebraic (SAT/Gröbner)** | A round function expressible as a *low-degree* system of polynomial equations relating a small number of variables — the trigger here is specifically the equation system's size and degree looking tractable for a modern SAT solver or Gröbner-basis computation, not a generic "try algebra on everything" impulse (companion history report `07` §1.1's XSL-attack dead-end is the standing cautionary tale about over-trusting this trigger without independent verification of the actual, not claimed, complexity) | Weak nonlinearity, low algebraic degree |
| **Statistical distinguishers, generally** | Any output stream or permutation output that shows *any* measurable deviation from uniform under a broad statistical test battery — the honest trigger here is usually "run the cheap test first, see if anything's there," rather than a specific structural hypothesis, making this the funnel's cheapest, least-targeted check (`02` Stage 4) | Incomplete avalanche, poor extraction |
| **Side-channel (timing, cache, power)** | Any implementation with secret-dependent branches, secret-dependent memory access, or secret-dependent operation *type* (not just operand value) visible directly in a reference implementation — the trigger is almost always found by reading code, not by analyzing the algorithm's abstract mathematics | Weak state layouts (in the implementation sense), floating-point/variable-time operations |
| **Fault attacks** | Any implementation where a single faulted computation, combined with the correct result of a redundant or structurally-related computation, could be combined algebraically to leak secret material — the RSA-CRT Bellcore-attack pattern (companion general-cryptography report `04` §1.5) is the standing template every fault-attack-triggered inspection is implicitly checking a new target against | Weak topology (specifically, redundant/decomposable computation paths) |
| **Microarchitectural / transient-execution attacks** | Not a property of the algorithm at all — the trigger is purely about the target CPU's speculative-execution behavior and is checked largely independent of which cipher is running on it (companion ARX report `04` §1.5's SLAP/FLOP discussion) | N/A — implementation/hardware-layer, not algorithm-layer |
| **Automatic cryptanalysis (MILP/SAT/SMT)** | Reached for once a manual, cheap check (`02` Stages 3–4) has narrowed the target enough that building a correct formal model is worth the researcher-time investment — covered in full triggering-logic detail in `06` | Any of the above, once manual triage has prioritized a specific lead |
| **Differential-neural / ML-assisted** | Reached for specifically when the target resembles a well-studied benchmark family (Speck/Simon/Simeck) with existing trained-model infrastructure to build on, or when the stakes (a live standardization candidate) justify the substantial training-infrastructure investment from scratch — covered in full in `06` and companion ARX report `04` §2.10 | Any of the above, at the highest investment tier |

---

## The meta-pattern across this entire table

Every row's "trigger" column, read together, restates `01` §1's core finding in a different form: **each attack family is reached for specifically because a cheap, early observation suggested that family's particular target assumption — nonuniform nonlinearity, symmetric structure, decomposable topology, low algebraic degree, secret-dependent timing — might be false for this specific design.** No experienced cryptanalyst runs the full table against every new specification exhaustively; the table is consulted *in the order the funnel in `02` surfaces triggers*, and the actual skill this report has spent its length trying to make explicit is not knowing that these fourteen-odd families exist (that's the companion reports' job), but recognizing, from a five-minute read of a new specification, *which row's trigger condition just lit up*.

Part `06` (`06-automation-and-the-modern-toolkit.md`) now covers, in the depth this table's automation rows only gestured at, how and when an expert actually reaches for MILP versus SAT versus a trained model — the decision layer sitting on top of the tooling your companion ARX report documents in technical depth.
